# GitHub Domain Glossary

## Repository

A repository is a storage space for project files, source code, documentation, branches, commits, issues, and pull requests.

## User

A user is a person who interacts with GitHub. A user can create repositories, commit code, open issues, create pull requests, and review changes.

## Branch

A branch is an independent line of development inside a repository.

## Commit

A commit is a recorded change in the repository history. It contains a message, author information, timestamp, and changed files.

## Pull Request

A pull request is a request to merge changes from one branch into another branch. It is commonly used for code review.

## Review

A review is feedback on a pull request. It can approve the changes, request changes, or leave comments.

## Issue

An issue is a task, bug report, question, or feature request tracked inside a repository.

## Label

A label is a marker used to categorize issues and pull requests.

## Maintainer

A maintainer is a user with enough permissions to manage the repository, review changes, and merge pull requests.

## CI

CI, or Continuous Integration, is an automated process that runs checks, builds, or tests after changes are pushed.

## Workflow

A workflow is an automated process that can be triggered by events such as pushes or pull requests.

## Merge

Merge is the process of integrating changes from one branch into another.

## Fork

A fork is a copy of a repository under another user or organization.

## Clone

Clone is the process of copying a repository from GitHub to a local machine.

## Push

Push is the process of sending local commits to a remote repository.

## Pull

Pull is the process of downloading changes from a remote repository to a local repository.
